# 基准案例 #1 阶段标注样板

Ticket `V5F84A` 用来验证阶段切分、盲标、知识候选、业务动作和历史回复评价能否形成一个闭环。本文件只记录标注建议；其中业务规则仍是 `observed`，没有经过负责人确认，不能直接供 AI 自动发送。

## 阶段 1：下单前询问超规格孕妇装定制

- 触发事件：`14800`
- 历史回复：`14801`，首次盲标后才能显示
- 生命周期：`presales`
- 客户目标：确认页面下拉框之外的孕妇装尺寸是否可以定制，以及应如何提交实际尺寸
- 意图：`presales_sizing`
- 所需事实：商品、客服政策
- 缺失信息：具体商品；实际尺寸；当前站点有效的尺寸提交入口；生产上限与附加费用
- 正确决策：核实商品与政策后回答；信息不足时先收集商品和尺寸
- 回复策略：`answer_policy`
- 业务动作：查询商品
- 自动化等级：当前为 `draft_review`
- 知识候选：`custom-size-outside-selector`
- 禁止承诺：未确认页面功能前不得要求客户使用备注框；未确认生产能力与费用前不得保证一定可以制作

阶段 1 不是简单复制 Alex 的回复。客户后来明确表示没有找到 comment box，因此这段历史回复最多只能作为知识冲突线索。

## 阶段 2：下单后补充并更新实际尺寸

- 触发事件：`14804`
- 历史回复：`14806`，首次盲标后才能显示
- 生命周期：`ordered`
- 客户目标：把正确尺寸关联到订单 `dad20230422-30890`，并确认客服能够收到和处理
- 意图：`presales_sizing`、`production_order_change`
- 主要意图：`production_order_change`
- 风险：`high`
- 所需事实：客户身份、订单、生产状态、历史沟通、客服政策
- 缺失信息：完整正确尺寸；订单归属；生产状态；另一封 support 邮件是否已关联；尺寸修改限制与费用
- 正确决策：先查询订单和生产状态，同时收集完整尺寸；更新成功后再确认
- 回复策略：`verify_before_action`
- 业务动作：查询订单、查询生产状态、收集尺寸、更新订单尺寸、确认操作结果
- 自动化等级：`draft_review`；接口和规则未验证前不能自动发送
- 知识候选：`post-order-measurement-update`
- 禁止承诺：更新成功前不得声称尺寸已经修改；未检查生产状态前不得保证仍可修改

## 验收点

1. Ticket 页面可以建立两个阶段，并调整尚未标注阶段的边界。
2. 阶段 1 盲标页面看不到事件 `14801` 及后续消息。
3. 阶段 2 盲标页面截止到事件 `14804`，看不到事件 `14806`。
4. 首次提交个人标注后，页面才展示所关联的历史客服回复用于评价。
5. 阶段可以关联已有知识，或创建状态为 `observed` 的知识候选。
6. 未验证知识、缺失信息、高风险或订单写操作会阻止 `auto_send`。
7. 金标准分别保存在阶段上，不再用一个结论覆盖整张 Ticket。
