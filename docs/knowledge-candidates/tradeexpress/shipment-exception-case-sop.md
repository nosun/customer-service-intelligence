## 适用范围

本文用于处理 `console-new` 中由系统自动创建的物流异常处理单。当前自动建单范围是待处理超时、待取件超时和未签收超时。处理未签收超时单时，可以继续记录核查后确认的地址、清关、拒收、退回、丢件、破损或拦截事实。

当前后台没有人工新建异常处理单的标准入口。模型虽然预留了轨迹停更、地址异常、清关异常、拒收、退回、丢件、破损、拦截等类型，但在建立受控创建入口或自动轨迹映射前，不能把这些类型描述为已经可以独立建单。后台页面当前仅允许 `administrator` 和 `manager` 角色访问和处理。

本文将问题分为三组：

| 问题组 | 典型类型 | 处理边界 |
| --- | --- | --- |
| 待处理异常 | 运单待处理超过 3 天 | 回到运单资料、抛送或订单操作处理，不套用取件后理赔规则 |
| 待取件异常 | 已生成面单但超过 3 天未取件 | 核对仓库和承运商；未取件时可走受控作废和新包裹流程 |
| 配送异常 | 已取件超过 15 天未签收 | 保留原运单，联系客户或物流商，跟进重发、重做、退款或理赔 |

超期只表示需要人工核查，不自动等于丢件、投递失败或责任结论。

## 系统职责

### `console-new`

- 保存物流异常处理单、负责人、跟进状态、客户诉求、承运商工单、责任、结果和日志；
- 决定是否不补发、包裹重发、订单重做或进入退款流程；
- 关联重发包裹、重做订单、退款参考和预计理赔；
- 在结案时按规则向 `tradeExpress` 回写最终物流结果。

### `tradeExpress`

- 保存原运单、物流单号、面单、轨迹、取件和费用事实；
- 检测超期运单并发布幂等异常事件；
- 持续同步原运单状态和轨迹，不因创建处理单而停止查询；
- 接收受控的最终投递结果回写，并校验状态冲突和幂等性；
- 以承运商对账数据保存实际理赔冲销。

业务系统不得直接修改另一个系统的数据库。跨系统数据通过受控 API 或事件传递。

## 自动发现规则

当前自动发现以下三类异常：

1. “待处理”状态超过 3 天；
2. 已生成面单且仍为“待取件”，超过 3 天未取件；
3. 已有取件时间、尚未妥投且未进入终态，超过 15 天未签收。

检测范围当前只扫描最近 180 天内符合条件的运单。成功、失败、废弃、合并、客户取消和拦截取消属于终态，不继续产生未签收超期事件。

系统以事件 ID 保证单次消费幂等，并以 `package_number:exception_type` 保证同一包裹、同一异常类型只有一个活动处理单。活动处理单收到后续重复信号时，只刷新最近发现时间和摘要；结案后 `active_key` 被释放，未来可为同一包裹创建新的异常记录。

## 操作前所需事实

处理前至少核对：

- 异常单编号、异常类型和当前处理状态；
- 订单号、包裹号、物流单号和物流渠道；
- `tradeExpress` 当前运单状态、取件时间、妥投时间和最近轨迹；
- 实物包裹所在位置；
- 客户当前诉求及最后一次有效确认；
- 承运商工单号、回复和承诺时限；
- 是否已经创建重发包裹、重做订单或退款；
- 是否需要理赔，以及理赔当前状态。

不得仅根据“超过阈值”直接判断包裹丢失或投递失败。

## 标准处理流程

### 1. 领取和首次记录

1. 在 `console-new` 的“物流异常处理”列表打开原处理单，不重复新建同类活动处理单。
2. 核对异常类型、包裹快照和 `tradeExpress` 当前物流事实。
3. 填写本次处理内容，并指定负责人。
4. 根据问题设置下一次跟进时间或截止时间。
5. 将状态改为“处理中”或相应等待状态。

每次保存都必须填写处理内容。操作日志只追加，不覆盖历史记录。

### 2. 联系客户或物流商

- 需要客户确认地址、电话、税号、清关资料或处理诉求时，设为“等待客户”。
- 需要承运商调查、改址、拦截、退回、丢件证明或理赔结果时，设为“等待物流商”。
- 记录承运商工单号、联系时间、回复内容和下一次跟进时间。
- 不在等待期间清空、覆盖或停止同步原运单事实。

### 3. 确认处理方案

| 实际情况 | 订单或售后动作 | 物流结果 |
| --- | --- | --- |
| 轨迹恢复正常，继续配送 | 继续跟踪 | “恢复正常”结案，不修改原运单状态 |
| 最终妥投 | 无需重发 | “最终妥投”结案并受控回写 |
| 原包裹已确认无法投递 | 根据商品和客户诉求选择重发、重做或退款 | “投递失败”结案并受控回写 |
| 未取件且面单、费用已经成功作废 | 创建新包裹或完成订单操作 | “作废”结案并受控回写 |
| 客户取消或退款，但包裹仍在运输 | 按订单或退款流程处理 | 不用客户状态覆盖物流事实 |
| 系统误报 | 记录判断依据 | “误报”结案，不修改原运单状态 |

重发边界：

- 商品可直接再次寄出时，使用“包裹重发”；
- 商品需要重新生产时，使用“订单重做”；
- 部分现货补寄目前没有标准功能，必须升级负责人确认；
- 新包裹独立创建运单、计费和跟踪，不能覆盖原包裹；
- 新包裹再次异常时，应在新包裹上建立新的异常处理单。

### 4. 理赔处理

1. 取得物流商调查结论或索赔编号，并记录责任方和依据。
2. 需要申请理赔时，将理赔状态设为“待申请”或“理赔中”。
3. 填写预计理赔金额时必须同时填写三位币种代码。
4. 理赔仍为“待申请”或“理赔中”时，处理单不能结案。
5. 预计金额只用于跟进，不作为最终财务事实。
6. 实际赔付、冲销或抵扣以 `tradeExpress` 中承运商对账单生成的 `claim_credit` 费用记录为准。

### 5. 结案

结案前必须：

1. 填写本次处理内容；
2. 选择明确的处理结果；
3. 完成或明确拒绝理赔；
4. 关联已产生的重发包裹、重做订单或退款参考；
5. 确认责任结论和证据已经记录；
6. 对“最终妥投”“投递失败”或“作废”执行受控结果回写。

`tradeExpress` 回写失败时，系统保留失败日志且异常单不结案。处理人员应修正冲突后使用同一异常单重试，不得绕过校验直接改数据库。

已结案的异常单不能再次修改。后续出现新的异常时，应创建新的处理单。

## 典型问题处理

### 拦截或取件后改址

1. 使用原异常处理单记录客户诉求和承运商工单号。
2. 承运商改址成功：原运单继续配送，结案为“恢复正常”或等待最终妥投。
3. 承运商只能退回：等待轨迹和实物去向确认，再选择重发、重做或退款。
4. 在包裹实际退回前，不得把运单改为废弃，也不得创建会造成重复发货的新包裹。

### 包裹退回

1. 保留原轨迹，确认退回原因和实物位置。
2. 确认客户是否仍需商品和最终收件地址。
3. 可直接寄出时创建重发包裹；需要生产时创建重做订单。
4. 在异常单中关联后续包裹或订单，记录责任和费用。

### 包裹丢失

1. 取得承运商丢失确认或索赔编号。
2. 记录责任、证据和预计理赔信息。
3. 按商品状态和客户诉求选择重发、重做或退款。
4. 理赔结论未完成时保持“理赔中”，不得提前结案。

### 运输破损

1. 收集外包装、面单和商品照片。
2. 记录损坏范围和责任证据。
3. 整包重新寄出使用“包裹重发”；需要重新制作使用“订单重做”。
4. 部分现货补寄暂停操作并升级负责人，不用整包重发代替。

## 状态说明

| 状态 | 含义 |
| --- | --- |
| 待领取 | 新建或自动发现，尚未明确负责人 |
| 处理中 | 已领取并正在核查或执行处理 |
| 等待客户 | 下一步依赖客户资料或确认 |
| 等待物流商 | 下一步依赖承运商调查或回复 |
| 换单处理中 | 已决定重新发货，正在关联新包裹或新订单 |
| 理赔中 | 正在申请或等待理赔结论 |
| 已完成 | 已选择结果、满足结案条件并保留完整记录 |

异常处理状态与原运单状态相互独立。例如，原运单可以保持“配送中”，异常处理单同时处于“等待物流商”。

## 提醒边界

系统每日汇总未结案数量和已超时数量。飞书提醒不包含订单号、包裹号、物流单号、后台链接或客户资料；处理明细统一进入 `console-new` 查看。

提醒用于推动人工处理，不自动改变原运单状态，也不自动创建重发、重做、退款或理赔记录。

## 禁止事项

- 禁止把超期信号直接判定为丢件、投递失败或责任结论。
- 禁止创建重复的同类活动处理单。
- 禁止覆盖或删除原物流单号、面单、轨迹和费用。
- 禁止将客户取消、退款或拒付直接写成物流投递失败。
- 禁止取件后使用普通“作废并重抛”流程。
- 禁止直接修改 `tradeExpress` 数据库回写结果。
- 禁止在没有处理内容或处理结果时结案。
- 禁止在理赔未完成时结案。
- 禁止把人工填写的预计理赔金额当作财务到账事实。
- 禁止让 RAG 或客服 AI 自动执行重发、重做、退款、取消、费用调整或结案。

## 升级规则

遇到以下情况必须升级：

- 系统状态与承运商事实冲突；
- 无法确认包裹是否取件、妥投或退回；
- 受控结果回写失败；
- 合并包裹、部分现货补寄或多订单共用实物包裹；
- 客户取消状态与物流结果冲突；
- 承运商拒绝提供调查结论或超过承诺期限；
- 涉及退款、赔付、费用调整或责任争议。

## 当前未自动化的能力

- 根据承运商轨迹异常代码自动识别丢件、拒收、退回、清关或地址异常；
- 通过后台人工新建非超期类异常处理单；
- 按不同渠道历史配送周期动态设置停更阈值；
- 根据真实燕文对账单列定义自动导入 `claim_credit`；
- 部分现货商品补寄。

这些内容不能被描述为当前已经上线的能力。
