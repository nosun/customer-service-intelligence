# MVP 范围与验收标准

## MVP 目标

让客服在一个页面中完成“读邮件、识别客户与订单、查看生产/物流上下文、获得 AI 建议、人工确认回复”，同时积累可用于改进分类和 SOP 的结构化数据。

## 建议范围

- 试点站点：`dressafford.com`。
- 客服邮箱：`support@dressafford-service.com`。
- 日均邮件规模：20 封以内。
- 主要语言：英语。
- 最近 90 天历史邮件加新邮件增量同步。
- 对所有来信进行售前/生产/物流/售后一级分类。
- 对经过样本确认的售前和售后二级类型进行深度处理。
- dorrisbridal、tradeManager、console-new、tradeExpress 的只读上下文。
- AI 分类、字段提取、摘要、知识检索和回复草稿。
- 人工编辑并确认发送。
- Case 动作、结果和审计记录。

在当前邮件量下，所有 AI 分类、关联和回复草稿均由客服人工复核。MVP 的主要价值是减少跨系统查询和整理时间，并沉淀可复用知识，而不是减少人工审核步骤。

考虑到账号尚未完成交接，MVP 分成两个可独立验收的阶段：

1. 离线阶段：使用脱敏导出样本完成解析、分类、订单号提取、Case 建模和 AI 评估。
2. 只读在线阶段：邮箱授权就绪后同步历史和新邮件，验证增量、去重和实际订单关联。

发送邮件和业务写操作不属于这两个阶段。

## 明确不包含

- AI 自动发送邮件。
- AI 自动退款、取消、改地址或补偿。
- 一次接入全部站点和全部历史邮件。
- 自研 LiveChat/Freshchat 替代品。
- 未经人工审核就发布 AI 生成的 SOP。
- 为未来场景预先建设复杂微服务或大数据平台。
- 在没有隔离措施、测试订单和回滚方案时直接用真实客户订单测试写操作。

## 业务验收场景

### 场景 1：订单进度咨询

收到邮件后，系统正确识别客户与订单，展示订单和 Work Order 状态，生成有事实依据的回复草稿。

### 场景 2：物流进度或异常

系统展示最新轨迹、异常信息和读取时间，AI 不在缺少轨迹时猜测预计送达时间。

### 场景 3：售后/退款诉求

系统正确识别为高风险或需审批，展示相关政策与历史信息，但不自动执行退款。

## 初始验收标准

- 历史同步可断点续跑，同一消息不会重复入库。
- 新邮件通常能在可接受时间内进入待处理列表；具体 SLA 由业务方确认。
- Gold Cases 中的一级分类、订单关联和关键字段达到双方确认的准确率。
- 所有 AI 结论都能看到使用的数据来源和读取时间。
- AI 无法确定客户、订单或政策时，明确要求人工处理，不编造事实。
- 回复发送前必须由人工确认，发送失败可重试且不会重复发送。
- 客服可以纠正分类、客户、订单、摘要和草稿。
- 每个 Case 可以记录 Resolution 和 Outcome。
- 所有敏感操作都有权限与审计记录。

## 需要业务方确定的量化指标

- [ ] 新邮件进入平台的目标延迟。
- [ ] 订单自动关联的最低可接受准确率。
- [ ] Case 一级/二级分类的最低可接受准确率。
- [ ] AI 草稿“无需修改/轻微修改/重写”的目标比例。
- [ ] 客服处理时间希望降低多少。
- [ ] 哪些错误属于阻断上线的问题。

## MVP 开始编码前的准入条件

- [ ] 第一批站点、邮箱和深度处理的二级 Case 类型已确定。
- [ ] 至少 20 个样本 Thread 已完成业务标注。
- [ ] 四个已有系统的事实源和只读接口已确认。
- [ ] 测试环境、测试订单和测试收发邮箱已准备。
- [ ] 邮件保存周期、权限范围和脱敏要求已确认。
- [ ] Gold Cases 和验收负责人已确定。

其中，离线样本阶段只要求前两项中的“站点/邮箱/Case 类型”和脱敏样本就绪，不需要等待 Gmail、LiveChat 或测试环境账号完成交接。
