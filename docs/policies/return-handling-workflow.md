# 售后退货与退款处理流程（候选 SOP）

整理日期：2026-10-22。状态：待业务审核，供 Ticket 调查、处理建议与邮件草稿使用；尚未发布到知识库或接入自动执行。

来源：用户提供的 Dorris Wedding 单个案例完整往来，以及当日读取的 Dorris Wedding 公开退货政策。案例是流程经验与个案承诺的证据，不构成各站点统一政策。本文不改变现行政策、不批准特定退款，也不将其他站点的规则覆盖到当前订单。

## 1. 目标与适用范围

成功标准：客服能确认退哪件、为什么退、依据什么、还有什么必须核实、可以提供什么方案、客户究竟接受了什么，以及退款是否真正发起。每封信推动当前步骤，只索取当前决定所需资料；尚未确定最终资格时，也能作有依据的阶段性回复。

适用于收到商品后的不合适、迟到、损坏、质量或错发争议，以及协商产生的退回退款、捐赠退款、保留商品补偿。不包含未发货取消；后者进入售中取消流程。换货意愿先记录，不在没有换货能力时承诺直接换货。

处理顺序：识别站点及适用政策 → 核对订单与商品 → 分别评估退货资格、责任和费用 → 只补必要证据 → 提供经批准的可行方案 → 记录明确接受 → 准备对应单据或核实凭证 → 核实履约结果 → 人工办理退款 → 核对渠道结果并通知。

## 2. 案例中哪些能复用，哪些不能

| 记录中的做法 | 可复用的处理方法 | 不能直接推广的内容 |
| --- | --- | --- |
| 标准尺码不合身，并且到货晚于预计日期及婚礼日期 | 同时识别不合身和迟到，核对结账时展示的预计时间、实际送达、活动日期及特殊承诺 | 迟到自动减免全部费用；标准码标签一致即证明实际尺寸无误 |
| 先确认衣服状态，没有索取测量照片 | 普通不合身与疑似制作偏差分支索证；充分利用已有资料 | 所有退货都不需要照片，或所有退货都必须量尺 |
| 客户称收到时没有黄色封签，客服允许继续 | 区分到货就没有、到货后拆除、是否有记录，不凭缺封签自动归责 | 缺封签一律可退；本案豁免是全站政策 |
| 中国退回、墨西哥退回、保留商品补偿 | 比较可用去向、明确净退款及费用范围，并解释客户承担事项 | 固定三选一；中国/墨西哥地址永久可用；固定 10%、50%、70% 或固定金额 |
| 商品编号、颜色及尺码出现矛盾 | 在发出可执行地址、发票和表格前锁定商品，暂停寄出 | 资料没对上时仍发地址，让客户先寄 |
| 客户得到超过退款金额的邮费报价 | 将退运经济性作为方案评估条件，升级替代方案 | 必须客户承担所有责任情形的运费；永不提供预付标签 |
| 客户以停止分期为接受条件 | 记录为有条件接受，澄清商家退款与支付计划的关系 | 部分退款自动停止全部分期；可用客户条件作为商家承诺 |
| 最后同意免退回退款 | 按最新明确接受的方案继续核实、安排；保留历史变更轨迹 | 客户接受即代表已退款，或所有高邮费案例均可免退回 |

本案最后可确认的是：客户接受 US$115 免退回退款方案。提供的记录没有后续商家退款发起、支付渠道成功或到账证据，不能写成退款已完成。

## 3. 先按问题分支，支持一单多原因

| 分支 | 核查重点 | 首封需要的信息 | 不应自动推导 |
| --- | --- | --- | --- |
| 普通不合身、过长、改变主意 | 标准/定制、适用窗口、商品状态及政策 | 当前记录缺失的退货原因与必要状态确认 | 客户买错；一定需身体和衣服测量照片 |
| 疑似制作尺寸偏差 | 下单尺码及测量值、实际衣服测量、工厂记录 | 对争议部位明确说明测量方式，索取最少必要证据 | 人台标签匹配即可排除偏差；不合身等于做错 |
| 迟到或错过活动 | 付款时预计日期/保证、实际送达、活动日期、首次反映时间 | 已有日期不再重复询问；只补影响决定的未知项 | 预计等于保证；迟到必然退运费或必然免责 |
| 收到时破损、脏污、错发或质量争议 | 原始申报、已有照片、包装、实际商品、物流/工厂调查 | 先看已有证据，只补缺失部位；有开箱视频则提供，没有则记录 | 必须有开箱视频才受理；所有损坏均属客户或末端承运商责任 |
| 送达记录与客户称未收到不符 | 签收和客户实际取得、承运调查 | 核对非收货声明及已取得证据 | 当作普通已收货退货，或单凭送达扫描结案 |

多原因分别评估，不让物流责任调查自动消灭普通退货诉求。若当前确需先澄清损坏才能决定处理方式，应说明调查目的、下一步和内部跟进，不把调查变成无期限等待或额外的通用退货门槛。

## 4. 分步操作与退出条件

### A. 建立申请与确认身份

核实站点、订单、申请人、具体商品行、数量、颜色、尺码、标准/定制、实付币种和费用。对照原始订单确认及客户描述，记录首次申请时间、送达时间和时区。保留首次申请时间，不因内部回复或索证耗时重新计算客户申请窗口。

商品存在矛盾时，只暂停该商品的可执行退货单据和退款操作，继续解释已确认内容。客户已确认的金额不反复要求确认。解决身份及商品范围后进入 B。

### B. 核查资格、责任与历史承诺

分别记录：常规资格是否满足、是否存在质量/迟到等责任争议、哪些费用依据何在、是否已有特批或对外承诺。使用对应站点适用的政策版本和原文；若订单期间与当前政策不同或生效时间不明，保留差异交业务确认，不静默追溯使用更不利条件。

正常退货核查未穿（试穿除外）、未洗、未改、当前状态及封签情况。声称到货已损坏的，不要求客户证明“到货时无损”才受理；分别记录到货损坏与之后是否进一步使用或修改。

封签缺失、定制商品质量争议、窗口争议、历史承诺冲突及费用责任不明进入个案判断，不能仅由一条常规排除规则自动拒绝。补证后仍无法决定时，形成内部核查项；能说清的内容先回复。

### C. 提供可履行的方案

只提供当前站点可用且已获授权的方案，一般一次 1–3 个。提出方案前评估目的地是否接收、必要文件、运输限制及成本。邮费尚未报价则标为未知，不承诺低价，不要求客户先花钱购买邮资。

| 方案 | 必须明确的条件 | 使用边界 |
| --- | --- | --- |
| 指定地点退回退款 | 目的地国家/城市、商品范围、净退款、运费承担、验收触发点、文件和期限 | 目的地和收件能力已核实；可先给国家城市与成本说明，身份匹配后再给最终地址 |
| 保留商品部分补偿 | 固定金额/币种、保留商品、无退回、费用范围 | 获得个案授权；不把客户接受视为自动支付 |
| 本地捐赠或寄售后补偿 | 可接受机构、捐赠/寄售哪一种、凭证要求、金额、触发点 | 机构接收不等于商品售出；两者是否均可用须明确，客户履行前约定 |
| 免退回和解退款 | 金额、范围、不要求退回/捐赠、是否替代其他方案、付款渠道说明 | 内部明确批准；不得由高退运费自动推导 |

每个方案单独算净退款，写明原运费、运输保障、加急费、税费是否包含，以及有没有额外扣款。固定净额意味着不能再默默扣一次入库费；不代表所有原始费用已经退还。

例：本案墨西哥 US$115 是约定净额，“不再扣 10%”不等于原运费、保障费另行全退。本案 US$68 是 US$135.99 的 50% 按美分四舍五入结果，不能因此生成一个全站 50% 捐赠政策。

### D. 确认客户选择与变更

区分询价、询问条款、明确接受、有条件接受和拒绝。有条件接受例：“只有停止剩余分期，我才接受 US$68”，在条件未满足或未澄清前不能标为已接受。

新提案记录准备替代哪些旧选项；除非双方另有明确约定，不能仅因发出新提案就抹掉旧承诺。客户明确接受替代方案后，将旧方案标为已替代并保留历史，避免金额叠加和多路履约；已退款或已经寄出时，先核对实际结果再变更。

本案顺序应记录为：选择墨西哥退回 US$115 → 邮费过高 → 提议本地 US$68（有条件接受，未达成）→ 提议免退回 US$115 → 客户明确接受。不能累计为 US$115 + US$68 + US$115。

### E. 发送最终文件或说明替代履约条件

退回方案：商品匹配后，核实当前收件人、地址、电话、承运要求、表格/发票、申报说明及有效期限，再一次性发送完整材料。使用目的地批准的单据和真实申报，不自行编造金额或用途。正式指引应明确最晚寄出日期、时区、追踪号提交方式及凭证留存要求。

Dorris Wedding 当前页面将 7 天寄出窗口起点写为收到退货表。建议完整、可执行材料齐备后才告知具体截止日；缺文件或内部延误时，记录原因和获批延期，不用提前发出地址消耗客户期限。其他站点按自身政策适配。

捐赠/寄售方案：事先给出本案凭证要求，例如机构名称、接收日期、商品识别、捐赠人关联。是否允许姓名后补、电子证明或其他替代材料由业务确认；不能办完后不断增加要求。免退回方案不再要求捐赠、寄售或退件追踪。

### F. 跟进履约并核查结果

退回：记录承运商、追踪号、寄出、目的地签收和检查结果，关联具体商品。收件确认不等于验货通过；如果约定以合作方收件为付款触发点，不得擅自增加售出等新条件。丢失、损坏、错件或拒收转人工处理，不能仅因追踪异常自动关案。

捐赠/寄售：按事先约定审核凭证，只补必要缺口，确认合格后不再重复索证。免退回：检查客户已明确接受及内部授权，不等待不存在的物流或凭证条件。

退运费过高、渠道无法承运、无开箱视频或无法取得原先要求的凭证，都应触发可行性复评，明确负责人及下次检查点；不能无限重复同一要求。

### G. 人工办理退款与通知

核对方案、接受记录、履约触发条件、商品范围、金额/币种、原交易、已退金额、已安排待执行金额及争议状态。按交易及商品核算可退款余额，防止多 Ticket、旧方案或部分退款重复处理。银行临时入账与永久撤销分别确认，不混为商家已退款。

本轮系统仅生成核查建议和本地草稿，退款执行留给有权限的人员。状态必须分别保存：已提出 → 已接受 → 已安排 → 已向支付渠道提交 → 渠道确认成功/失败 → 客户到账是否有证据。对外通知采用实际取得的状态，不把“已安排”写成“已收到”。

原路退款遇到换卡或失效等问题，通过支付渠道核实，不向客户索取完整卡号或安全码。争议/拒付与退款并存时核对渠道规则和实际资金，不笼统要求客户先撤争议。

## 5. PayPal / Afterpay 等分期支付的单独说明

商家控制本笔交易的退款发起，分期提供方决定余额、扣款日程和资金分配。只看到订单收款，不能证明客户已还完、还欠多少或剩余分期已停止。

部分退款可能冲减未付余额、返还已付金额或分别分配，具体以渠道对本笔计划的确认结果为准。不得承诺“收到退款现金，同时剩余分期全部取消”，也不能从一次退款成功推导计划已结清。客户应遵循渠道当前付款指示，直至渠道确认调整。

本案提供了 PayPal 说明链接，但本文未重新核验该帮助页面的完整条款；用于客户邮件前应核实当前内容及客户实际产品/地区。不把 PayPal 的说明复制成 Afterpay 的保证。

## 6. 核查信息、办理状态与缺口分开

建议沿用现有 Ticket 输入、业务快照和审计记录，先按下列清单保存，暂不增加一套通用流程引擎。

| 信息组 | 最少记录 |
| --- | --- |
| 范围及来源 | 站点、订单/商品行、退货数量、申请人匹配、政策版本、原始消息/指南引用 |
| 时间与原因 | 收货、首次申请、活动/预计时间（有关时）、问题分支、责任判断及未知项 |
| 条件及证据 | 商品状态、封签到货情况、已有附件是否实际审核、补证目的、工厂/物流原文及时间 |
| 方案 | 方案版本、选项、金额/币种、费用范围、触发条件、去向、文件版本、旧方案关联 |
| 接受 | 提出/询问/有条件接受/明确接受/拒绝/已替代，客户原文和时间 |
| 履约 | 指引与完整文件发送时间、截止日依据、追踪/签收/验货或捐赠凭证审核 |
| 财务 | 原交易、已退/待退金额、争议/撤销、商家提交与渠道结果，分期调整独立记录 |
| 当前步骤 | 下一步、由谁处理、缺什么、下次核查点、允许向客户说明的内容 |

“缺少退货资格依据”只限制资格结论；“缺少退款结果”只限制完成声明。不是任何缺口都阻断安抚、解释已查事实和询问必要信息。真实身份矛盾、金额冲突或未获授权承诺则限制对应行动。

## 7. 阶段邮件模板候选

以下是待审核的内容骨架，用于提取流程和后续模板，不是直接导入当前模板选择器的 JSON。当前选择器的变量支持尚不能覆盖所有退款字段，后续接入时须补契约与回放。变量只有取得来源后才能填充；可选段不适用就删除；问候与签名按当前站点，不默认沿用 Dorris Wedding。

### RET-01 普通不合身：确认必要条件

适用：已锁定商品、常规退货条件仍需确认，未作批准。

```text
Dear {{customer_name}},

I’m sorry that the dress did not fit as you hoped.

To help us assess your return request, please confirm that, apart from trying it on, the dress has not been worn, washed or altered, and let us know its current condition.

{{only_the_other_information_needed_for_this_case}}

Please wait for our approved return instructions before mailing the dress.

Warm regards,
{{site_signature}}
```

封签问题仅在本案确需核实时询问，缺失结论不预设。已有状态确认不重复问。

{{approved_options_with_net_amount_currency_costs_and_conditions}}

## 8. 与现有 Ticket v2 的接入方式

沿用 [调查与回复生成设计](../architecture/ticket-investigation-reply-workflow.md)：售后下分别规划退货、物流损坏、商品偏差、分期疑问等请求；调查后形成可说内容，使用当前阶段模板，再独立审核。

审核除事实和政策外，检查：是否重复索证、是否新增接受条件、是否把有条件接受当作确认、是否正确替代旧方案、是否把退款和分期混为一谈、是否混淆安排与提交/到账、是否给了当前步骤可行的下一步。

## 10. 后续回放验收场景

| 场景 | 应有结果 |
| --- | --- |
| 标准码不合适，无制作偏差主张 | 只确认必要状态，不默认索取全身与量尺照片 |
| 人台标签相同但客户主张尺寸偏差 | 不能用标签直接否认；针对争议部位取证 |
| 原始损坏与不合身同时存在 | 两个诉求保留，不用原始损坏强制否定正常状态条件 |
| 到货即无封签，现行政策要求封签 | 显示差异和个案待判，不自动拒绝或自动豁免 |
| 已有照片，物流希望开箱视频但客户没有 | 不重复索取已审核资料；继续评估替代证据与跟进 |
| 申请及时，内部调查跨过窗口 | 保留首次申请时间，不自动判定客户逾期 |
| 商品描述矛盾、客户已经接受金额 | 不反复确认金额，不发可执行错单文件，不让客户先寄 |
| 退款 US$115，客户理解成所有运费另退 | 明确净额及范围，不扩大承诺或再扣未约定费用 |
| 邮费高于退款且尚无替代授权 | 记录不可行性并升级，不自行批准免退回 |
| 客户以停止分期为接受条件 | 保留有条件接受，不执行、不承诺渠道计划已取消 |
| 新方案提出但未接受 | 不叠加退款、不静默抹掉旧承诺 |
| 客户接受免退回 US$115，无执行记录 | 可确认协议和获授权下一步，不宣称已经退款 |
| 同单多 Ticket、已有部分退款或争议入账 | 核对余额及真实资金状态，避免重复退款 |

本文验收是流程与来源一致性核查；这些是后续自动化回放的候选场景，本次未执行退款接口或将其标记为已通过测试。
