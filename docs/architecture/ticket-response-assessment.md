# Ticket 回应判断与案件进度：架构复核及实施

日期：2026-10-22。范围：在 v2 候选链路上完善上下文、当前进度及回应判断；不改变正式发布门禁。

## 结论

现有 Laravel 管事实、权限、版本和审计，n8n 管有限调查与独立复核，知识库管审核过的流程和模板，这个职责划分继续保留。现有不足是以“生成一封邮件”为中心，缺少正常的等待结果，且跨 Ticket 的同一订单上下文没有进入输入指纹。单纯增加提示词不足以解决这些问题。

不创建第二套案件引擎，不将 AI 摘要作为业务系统的真实状态。每次从有来源的沟通与事实重新评估，评估保存在当前 WorkItem；新消息、关联记录或指南变化使旧结果过期。

## 四个维度分开

| 维度 | 例子 | 边界 |
| --- | --- | --- |
| 业务阶段 | 售前、售中、售后 | 同一案件可能有多项业务 |
| 当前进度 | 等客户资料、等内部调查、方案协商、待退回、待审核凭证、可办理退款 | 是有依据的当前判断，不是已执行结果 |
| 回应选择 | 实质回复、简短确认、暂不回复 | 暂不回复是正常结果，仍需人工审核及明确下一步 |
| 真实动作 | 取消、退款提交、渠道结算 | 以业务系统结果为准，不从客户接受或 AI 判断推导 |

## 上下文边界

关联上下文限同渠道账号、同站点、同客户邮箱、同明确关联订单；排除同客户其他订单和未来消息。缺少明确订单时不猜测关联。已关闭的相关会话仍是历史证据。回放账号不连接真实会话。

当前与关联消息均保留事件 ID、会话 ID、时间及来源。关联指南仅提供历史背景，不能作为当前操作人授权；历史客服承诺可供独立审核，但不证明已实际退款。上下文过多时明确显示不完整，并限制自动给出不回复结论，不静默截断。

新正文与引用旧信分别提供，保留原文供核查。仅对明确的邮件引用分隔符拆分，不猜测删除内容。附件元数据不代表实际审核了图片或视频。

## 流程

1. 冻结当前消息、相关历史及版本指纹。
2. 理解最新消息在回应哪一个问题；本次可能仅是资料进度更新。
3. 按需取得事实，在现有评估节点内生成当前进度和回应建议，无需再加一个自由规划代理。
4. Laravel 校验事件引用、状态枚举、等待对象及下一步；不接受无依据的沉默结论。
5. 实质回复或简短确认进入生成与独立审核；暂不回复跳过作者，直接独立审核回应决定。
6. 只有两次判断一致且校验通过，才保存 `no_reply` 正常结果且不创建空草稿。未通过保存为需人工判断，不自动静默。
7. 所有结果都展示当前进度、依据、下一步和历史完整性。跟进日期是建议；本轮不创建通知或后台定时任务。

简单确认/纯资料进度可使用 `conversation_update` 意图，避免仅为确认“周六发视频”查询订单 API。只要包含退款、资格、执行或金额声明，仍走对应业务核查，不得以此绕过事实要求。

## 11104 的验收标准

客户表示保留包装、内袋也破了、出差中周六补拍视频。应识别为等待客户资料，建议简短确认，澄清是当前包装/损坏视频而非已存在的开箱视频；不得声称视频已收到、认定承运责任、重新索取开包前录像或承诺退款。同订单 11861 作为背景；不把其指南自动升级为当前执行授权。

## 鲁棒性验证

覆盖串站点/串账号/串订单隔离、关联新消息及指南使旧输入失效、时间边界、引用分离、历史不完整、不回复缺乏引用、审核分歧、新问题不可仅按关键词静默、正常无草稿结束、既有取消与退款回归。n8n 分支代码须执行测试；本地源码测试与真实导入、模型回放、人工发布审核分别报告。

## 当前实现及验证边界

已在现有 v2 中实现关联历史、输入指纹、引用分离、`TicketResponseAssessment`、三种回应选择、独立不回复审核分支与后台展示。旧 v2 调用未提供回应判断时保守回到实质回复，不允许隐式静默。暂不回复必须是纯 `conversation_update`，附当前消息及历史客服消息依据，说明等待对象和下一步；复杂业务不允许走此捷径。

同订单关联记录受同账号、站点、邮箱约束，当前实现只匹配已明确关联的订单号；不会自动从任意旧邮件推断订单归属。关联历史上限 20 个会话、500 条公开消息，超限显示不完整并禁止自动通过不回复判断。当前会话仍保留全部原始消息。附件仍限元数据，内部备注与附件内容识别不在本次范围。

关联新消息、指南或版本变化使生成结果过期，后台同时检查已有草稿与无草稿的回应建议；旧判断不能继续当作当前建议。未添加定时提醒执行器，跟进日期只作为人工建议展示。人工是否执行等待、回复或更新 HelpDesk 状态仍由客服决定。

真实本地 n8n 冻结回放结果：11104 类视频进度为 `acknowledge` 并生成简短法语确认；已解决后的感谢为 `no_reply`，不创建空草稿；视频进度加退运费问题为 `reply`；带停止分期条件的退款接受为 `reply`，保留条件未达成；12067 类未来取消回归为可审核草稿。未对真实 11104 或其他客户发送邮件或修改订单。

回放集新增四个回应判断场景，合计 78 条；新门禁要求回应判断错误率为零，并将 `needs_review` 视为未放行结果。独立审核仍可能与规划共享模型偏差，不能替代人工审核；完整回放和人工发布审核未完成，继续保持 `evaluating`，不切换默认入口。

本轮最终自动化验证：Feature 246 条、1,445 个断言；Unit 62 条、398 个断言，均通过。Pint、工作流代码节点执行检查及 `git diff --check` 通过。真实 n8n 五个定向场景通过上述预期，但不能据此声明全部 78 条回放或人工发布审核已通过。
